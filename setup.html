Run it yourself

Set up the notebooks on MetaCentrum OnDemand

The pages on this site are read-only. To run the notebooks with your own account, start JupyterLab on OnDemand and follow these steps. It takes about ten minutes the first time.

Want it done for you? BinderHub sets everything up automatically, but it may not be working properly at the moment. More below.

1Before you start

  • A MetaCentrum account. You sign in to OnDemand with your e-INFRA CZ / MetaCentrum login; if you do not have one, apply at metavo.metacentrum.cz.
  • Credentials only for the services you want to try. Notebooks 00, 05, 06 and 07 need none.
#NotebookNeeds
00Environment Check & DiagnosticsNone
01S3 Object Storage IntegrationS3 endpoint, access key, secret key, bucket
02Invenio Repository Integration (EOSC CZ / NRP)NRP API token
03OpenStack API IntegrationOpenStack application credentials
04Open WebUI Chat API IntegrationAI API token
05GPU Container with AI ModelNone
06R Kernel DemonstrationNone (R kernel required)
07MATLAB Kernel DemonstrationNone (MATLAB kernel required)

2Start JupyterLab on OnDemand

  1. Open ondemand.metacentrum.cz and sign in with your e-INFRA CZ / MetaCentrum login.
  2. Under Interactive Apps, choose Jupyter.
  3. Pick the resources for the session. A couple of CPU cores, a few GB of memory and a few hours of walltime are enough for every notebook except 05; request a GPU only if you want to run notebook 05.
  4. Launch the session, wait until it is running, then connect to it. JupyterLab opens in a new tab.
The OnDemand form changes from time to time. MetaCentrum's Jupyter documentation describes the current options.

3Download the notebooks

In JupyterLab, open a terminal (File → New → Terminal) and clone the repository into your home directory:

git clone https://github.com/OmarIbrahim22/metacentrum-notebooks.git
cd metacentrum-notebooks

4Install the dependencies

Still in the terminal, inside the metacentrum-notebooks folder, install everything the notebooks use. JupyterLab itself is already there.

pip install -e ".[all]"

To install only what one notebook needs, use its extra instead of all: s3 (01), invenio (02), openstack (03) or openwebui (04). Notebooks 00 and 05 need nothing extra.

If pip says it cannot write to the install location, run the same command with --user added. A notebook never installs anything itself; if a package is missing, its first cell prints the exact command to run.

5Set up your credentials

  1. Open notebooks/00_environment_check.ipynb and run all cells (Run → Run All Cells).
  2. It checks your environment, then its setup wizard asks for each credential and saves them to ~/.config/mcnb/env in your home directory. They are never written into the repository.

Prefer a file? Copy env.example to .env in the repository folder and fill in your values; each variable links to the page where you get it.

6Run a notebook

Open any notebook from the notebooks folder and run it top to bottom. Each one is self-contained.

  • 01 and 02 create one test object / one draft record and delete it again in their Cleanup section. 03 and 04 only read.
  • 05 needs a session with a GPU. OnDemand runs Jupyter inside Apptainer, so the notebook uses Apptainer, not Docker.
  • 06 runs on the R kernel and 07 on the MATLAB kernel; switch with Kernel → Change Kernel.

7Coming back later

A session stops when its walltime runs out. Start a new Jupyter session the same way; the cloned folder and your credentials stay in your home directory. If a notebook then reports a missing package, run the install command from step 4 again.

Prefer a guided setup? Use BinderHub

BinderHub opens a ready-made Jupyter session with the notebooks and every dependency already installed, so steps 2 to 4 are done for you. You still sign in with your e-INFRA CZ / MetaCentrum login and enter your own credentials.

BinderHub may not be working properly at the moment. If the session does not start, use the OnDemand steps above instead.
